### Verified problem reports

- A [January 2026 Distill forum report and staff response](https://forums.distill.io/t/indication-when-local-monitor-is-not-active/5883) describe difficulty recognizing inactive local monitors; the check log is the documented signal. This is one report, not evidence of a general failure rate. It supports keeping overdue/last-success indicators prominent.
- A [September 2026 changedetection.io discussion](https://github.com/dgtlmoon/changedetection.io/discussions/4465) reports a working test email but missing automatic alerts and difficulty finding diagnostics. It illustrates the distinction between detecting a change, satisfying a condition and delivering a notification; it does not establish a root cause across installations.
- [Open Terms Archive maintenance documentation](https://docs.opentermsarchive.org/terms/explanation/declarations-maintenance/) distinguishes unreachable, unextractable and noisy documents. This is project guidance rather than a user complaint. It informs PageSentinel's health/extraction/selector distinctions.

No verified comparative complaint evidence was established here for every competitor or every requested complaint category. Pricing restrictions, source availability and privacy models are documented product facts, not automatically user complaints.

### Decisions and hypotheses

Implemented choices: explicit health, persisted inbox, last-good baselines, policy groups/discovery, conservative local summaries, manual-confirmed repairs, cumulative thresholds, encrypted backups and contextual advanced controls. These address specific workflow problems while keeping the existing static privacy model.

Unproven hypotheses: beginners will understand the three overview actions more easily; grouped local policies will be useful enough to differentiate the product; the narrower static model will suit users willing to trade rendering breadth for simpler access controls. Validate these with the [participant plan](USABILITY.md). No competitor installation, equal-task step-count study or human participant testing was performed in this environment.

### Chrome API verification

[Scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting) supports user-initiated current-tab inspection through activeTab or host access. [Alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms) can be delayed by sleep and do not wake the device. These documented constraints inform discovery and health copy. Native Web Crypto [encryption](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt) and [key derivation](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey) provide the implemented backup primitives; no custom cipher is introduced.

## Naming

[pagesentinel.com](https://pagesentinel.com/) already markets commercial website change monitoring, including policy/pricing changes and historical evidence. This is a direct naming conflict regardless of trademark registration. PageSentinel remains a working title in `librerob/pagesentinel` and is not ready for a final store listing.

Focused indexed searches for `PageSentinel` on GitHub and the Chrome Web Store did not establish a unique available name. Search absence is not clearance. Similar names include WebSentinel, PageSentry and PagePulse; avoid claiming first use or ownership.

The [UK IPO search entry point](https://www.gov.uk/search-for-trademark) was inspected. [WIPO Global Brand Database](https://branddb.wipo.int/) presented a verification challenge, so a registry-level clearance search was not completed. No trademark-availability conclusion is made. A jurisdiction/class-specific naming review is still required before final branding.

## Chrome API decisions

- [Alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms): persist schedules and recreate missing alarms. Chrome 120 supports a 30-second minimum, but this product uses at least one-minute custom intervals and a 15-minute default. Delays and sleep are disclosed.
- [ActiveTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) and [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting): temporary user-initiated selection, not background broad-site access.
- [Permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions): optional origin-specific grants requested in a direct user gesture. Revocation pauses monitors.
- [Cross-origin requests](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests): fetch from the worker only with host permission, without credentials, and with redirects rejected.
- [Offscreen](https://developer.chrome.com/docs/extensions/reference/api/offscreen): service workers have no DOM parser. A bundled inert parser is used instead; no offscreen permission or hidden tabs are necessary for static HTML.
- [Notifications](https://developer.chrome.com/docs/extensions/reference/api/notifications) and [storage](https://developer.chrome.com/docs/extensions/reference/api/storage): native local notifications and small local preferences. History uses IndexedDB.

No universal dynamic-page, real-time, signed-in-session, uptime, or legal-risk claims are made.
