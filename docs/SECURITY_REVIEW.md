# Implementation security review

Reviewed the static fetch/extraction pipeline, URL/configuration validation, UI rendering, worker messages, picker/discovery injection, storage/migrations, backups, dependencies and CI. This is a source/test-based engineering review, not an independent penetration test or certification. The build remains a preview.

## Confirmed fix

The previous public-domain validator checked local suffixes before removing a trailing DNS dot. A name such as `app.local.` could pass its string checks. The URL parser now canonicalizes the final dot before suffix checks and before constructing permission patterns. Regression tests cover local suffix variants, alternate IPv4 spellings, IPv6, credentials, unsupported schemes, malformed DNS labels and public internationalized names. No private host was contacted to prove this validation failure.

The earlier cumulative-threshold, unrelated-login-modal, international-price and full-scan storage problems were verified as already fixed rather than reintroduced. Additional regression cases cover reversions, threshold changes, group migrations and stable event IDs.

## Threat boundaries

| Threat                                    | Mitigation and evidence                                                                                                                                                                                                                      | Remaining boundary                                                                                                                                                                      |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Malicious page markup or scripts          | Worker uses a bundled inert parser; scripts/styles/frames are removed; React renders text nodes. Controlled hostile-markup extraction and escaped diff tests remain.                                                                         | CSS visibility is not reproduced; recognizable authentication/challenge detection is heuristic.                                                                                         |
| Local/private targets and redirect abuse  | Validate public HTTP(S) URLs before grants, fetch, storage and injection; reject IP/local names and embedded credentials. Fetch rejects every redirect before destination contact.                                                           | Chrome resolves DNS; a public-looking name may resolve to a private address. No DNS pinning or complete rebinding defense is claimed.                                                   |
| Spoofed privileged messages               | Exact extension UI URL/sender checks protect management commands. Picker messages require extension sender, top frame and Chrome tab metadata. Repair IDs come from session state and must match a stored monitor and final tab URL.         | A monitored page can manipulate its own text/links. Users must review targets and evidence.                                                                                             |
| Unauthorized policy crawling              | User-initiated link inspection only, bounded to observed links. No candidate fetch until selection and explicit per-origin grants. Dashboard discovery uses the existing static fetch path.                                                  | A discovery heuristic can propose an irrelevant external document; association is not proof of company ownership.                                                                       |
| Bad imports and corrupted encrypted files | Byte bounds, schema validation, fresh IDs, paused copies and atomic writes. AES-GCM authentication rejects wrong passwords/tampering; fixed KDF cost prevents attacker-selected iteration counts.                                            | Archival versions are not imported as live baselines. No recovery of lost passphrases. Cryptography has tests, not an external audit.                                                   |
| Excessive work/storage                    | Response/time/text limits; bounded list/discovery/bulk work; serial worker queue; backoff; byte ledger; targeted history pagination. New monitor creation cannot bypass the byte budget after count-cap removal.                             | Large watchlists can be overdue. Metadata needed to report an existing failure remains writable at the logical budget boundary. Logical accounting excludes physical database overhead. |
| Interrupted checks/migrations             | Successful baseline/reference, history, retention and byte ledger commit atomically; failures preserve prior good state. Version-change transactions preserve v1/v2 data or roll back. Persisted leases and alarms recover interrupted work. | Chrome/OS crashes, profile corruption or external deletion may require an exported backup.                                                                                              |
| Notification loss/duplication             | Change IDs persist with snapshots before OS requests. Identical results do not duplicate history. Snoozed changes remain unread in the inbox.                                                                                                | A crash between commit and OS request can lose that OS alert. OS delivery is not exactly-once or guaranteed.                                                                            |
| Local profile access                      | No developer backend or sync; deletion/export/grant-removal controls. Optional encrypted backup files.                                                                                                                                       | Normal profile storage is plaintext and accessible to profile users, malware or profile backups.                                                                                        |
| Supply chain and CI                       | Locked packages, `npm ci --ignore-scripts`, development-only axe, bundled runtime notices, zero-vulnerability audit at implementation, immutable action pins and read-only PR workflow token.                                                | Audit databases and dependencies change. The opt-in main-branch release workflow has write permission because it publishes; it is not invoked by PR code.                               |

## Permission and network review

No new manifest permissions or mandatory host grants were added. `scripting` now also supports a current-tab policy-link read through existing user-initiated activeTab/host authorization. The shipping permission list remains alarms, storage, notifications, activeTab and scripting, plus optional HTTP/HTTPS host patterns. Credentials/referrers remain omitted; redirects, bounded downloads and URL validation remain in the same fetch pipeline. No rendered monitoring or secondary unrestricted fetch path was added.

The public compatibility probe is a development script with an explicit fixed list; it is not bundled, does not run in ordinary monitoring and retains only result metadata. Browser fixture tests pre-grant one synthetic host in a temporary manifest; the shipping manifest is separately validated.

Native host-permission UI, OS notification appearance, assistive technology and human usability remain supervised checks. Automated passing results do not certify the entire threat model.
